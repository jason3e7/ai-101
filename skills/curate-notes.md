# /curate-notes

給我一篇筆記的標題與摘要，我判斷它該放在 `06-外部觀點/` 根目錄，還是移入 `06-外部觀點/參考/`。

## 判斷標準 — Triage Criteria

### 放根目錄（值得反覆查閱）

符合以下任一條件：

1. **第一手來源**：作者親身實踐、有直接存取權，而非轉述別人的研究或作品
2. **具體數字佐證**：有可以驗證的資料（案例數據、實驗結果、具體時間 / 成本）
3. **可直接改變工作方式**：讀完你會知道「我明天開始要這樣做」，不只是「這很有趣」
4. **持久參考價值**：一年後仍然值得回來查，不會因模型更新或工具換代而失效
5. **提供決策框架**：幫你在多個選項中做判斷（速查表、情境地圖、方法論）

### 移入 `參考/`（知道就好）

出現以下任一情況：

- 轉述他人研究、論文、演講（一手是作者，你看的是二手）
- 工具介紹 / 產品公告（價值在工具本身，不在這篇筆記）
- 新聞報導（時效性高，不會反覆查）
- 觀點或評論（有趣但不影響你怎麼做事）
- 短效觀察（模型版本評測、社群討論快照）

## 使用方式 — How to Use

提供：
- 筆記標題
- 一到兩句描述（筆記在說什麼、作者是誰）

我回傳：
- **根目錄** 或 **參考/**
- 一句話說明理由
- 如果邊界模糊，說明哪個條件讓我猶豫

## 範例 — Examples

> 標題：寫程式已被 AI 解完了 — Boris Cherny（Claude Code 之父）
> 摘要：Claude Code 創辦人分享自己 2026 年起不再手動寫程式，每天跑 5-10 個 session，單日推 150 個 PR

→ **根目錄**。第一手來源（本人說）、具體數字、直接改變工作模式。

---

> 標題：Is Grep All You Need：向量搜尋不如 grep 的 PwC 研究
> 摘要：整理 PwC 論文的五個結論，Grep 在精確查找場景全面勝過向量搜尋

→ **參考/**。轉述研究結論（一手是論文，這篇是摘要），讀完不會改變你今天怎麼架系統。
