# lab01 訊號實驗紀錄 — Signal Experiments Log

> [!NOTE] 這是什麼
> lab01 baseline 只算 `——` 密度. 這篇記錄我們在同一批資料 (2026 鐵人賽 15057 篇) 上, 陸續試過的幾個「疑似 AI 味」訊號, 為什麼看起來合理但最後幾乎都誤判, 以及從誤判本身學到什麼.

> **TL;DR (EN):** Each single-character or single-pattern signal turned out to detect *a specific writing style* (definition-dash format, first-person diary, tutor-voice teaching) rather than "AI-written" itself. Multi-signal stacking or a pre-ChatGPT baseline is needed before any of these can be called a real AI-tell.

```markdown
# 一個訊號常常只抓到一種寫作風格, 不是 AI 本身
* V01: `——` 密度 (baseline)
    * 抓到「A —— B」定義符 (產品介紹、工具懶人包)
    * 也抓到英文小說式敘事 (誤判)
* V02a: 我 / 你 字元計數
    * 抓到第一人稱散文、心靈日記
    * 都不像 AI (誤判)
* V02b: 我 + 你 同句共現
    * 抓到「我來教你」的家教口吻
    * 靠近 AI 味, 但也抓到 PM/職涯建議文 (誤判)
* 通則
    * 單訊號 = 只能抓「特定寫作風格」
    * 需要多訊號疊加, 或跟 pre-ChatGPT baseline 對照
```

## V01: 雙破折號密度 (baseline)

**假設**: 中文技術文章幾乎不用 `——`, AI (Claude / GPT 未特別壓制時) 極愛用. 純字元計數, 一眼可辨.

**方法**: `analyze.py`. 密度 = `——` 次數 / 正文總字數. 排除 `<pre>` 程式碼區塊.

**結果 (Top 3 每千字命中最高)**:

| 排名 | 每千字 | 文章 |
|---:|---:|:---|
| 1 | 17.51 | [Day01 用 Claude 從零打造一個軟體產品](https://ithelp.ithome.com.tw/articles/10411391) |
| 2 | 14.29 | [Day 12｜第 6 章：流程再造（下）](https://ithelp.ithome.com.tw/articles/10416320) |
| 3 | 13.49 | [Day25：另一套 mpv 懶人包](https://ithelp.ithome.com.tw/articles/10402332) |

**觀察 — 三篇的 `——` 都不是拿來當「插入語氣」用**, 而是拿來當「A → B」的定義符:

- #1「產品發想 ——這個東西到底該不該做？」「Claude Code ——工程師的好夥伴」 — 概念 → 解釋
- #3「sub-assrt.lua —— 射手網字幕下載」「thumbfast —— 縮圖腳本」 — 工具名 → 說明
- #2「連便利貼都沒有——大尚的記憶力驚人」「不是坐在對面——是坐在旁邊」 — 補充語氣 (英文小說式)

中文標準寫法會用「：」或「，」代替. `——` 這個用法是**西化 / AI 化的排版習慣**.

**誤判**: #2 是小說敘事, 破折號是英文文學傳統, 不像 AI. #1、#3 看起來像 AI 味, 但也可能只是作者受過英文寫作訓練. 單靠 `——` 密度沒辦法區分.

## V02a: 「我」「你」字元計數

**假設**: 技術文章多半用被動或第三人稱寫 (使用者、可以觀察到), 直接稱代詞 (我 / 你) 較少見. AI 愛用會話式語氣, 密度應該高.

**方法**: `analyzeV02.py` (第一版, 之後被 V02b 覆蓋). 分別數 `我` 跟 `你` 出現次數, 主排名用合計密度 (我 + 你) / 總字數.

**結果**:
- 90.8% 的文章至少出現一次
- 全體每千字 5.04 (我 3.61 + 你 1.43)

**Top 20 誤判**: 前面幾乎全是「日記/觀察/心情分享」風格:

- #1「深呼吸的時刻」95.41/千字 — 開源大佬的**脆弱心靈日記**
- #2、3、4 都在同一系列
- #7「TL 的荒謬觀察日誌」
- #8「AI 從聊天閨蜜到執行助理」

**原因**: 「我 / 你」是很常見的字元, 只要作者用第一人稱寫散文就會爆表. 這個指標抓的是「有沒有散文化」, 不是「有沒有 AI 味」.

## V02b: 「我」「你」同句共現

**修正**: 從純字元計數改成**句子級共現** — 一個句子裡同時出現「我」跟「你」才算 1 次. 想抓「我來教你」「你可以照我這樣做」這種家教式口吻.

**方法**: `analyzeV02.py` (現行版本). 句子邊界用 `。？！` 或換行. 主排名用共現句 / 總句數.

**結果**:
- 5399 共現句 / 130 萬總句 = 0.41%
- 19.1% 的文章至少有 1 個共現句

**Top 排名有變化**, 心靈日記類退了 (深呼吸的時刻降到 #13). 新面孔:

- 系列 **「管理職PM的敏捷團隊賦能實踐航道」** — top 20 佔 6 席
- 系列 **「跌跌撞撞的轉職路：面試馬拉松」** — top 20 佔 4 席
- 「Day 6：Git 的靈魂三雄」— Git 教學

**部分符合假設** (家教式教學) 但**還是有誤判**:
- 前幾名爆高的都是**句數超少**的短文 (1-3 句), 1 句共現就 33-100%. 現有排行沒設門檻
- PM / 職涯建議文用「我 + 你」很自然 (「我建議你」「我覺得你可以」), 不代表 AI 寫的
- 真正的 AI 家教文有時候反而分散在「我」跟「你」不同句, 沒被抓到

## 共通觀察與下一步

**三次嘗試都撞到同一堵牆**: 一個訊號只能抓「一種寫作風格」, 不是「AI 味」本身:

| 訊號 | 抓到的其實是 |
|:---|:---|
| `——` 密度 | 定義式排版 (或英文小說式) |
| 我 / 你 字元 | 第一人稱散文 |
| 我 + 你 共現 | 家教式教學 / 建議文 |

**下一步方向**:

1. **多訊號疊加**: `——` + 我/你共現 + 三段式結構 + 冗詞掃描, 交叉才有鑑別力. 對應 README「後續 lab 可能延伸」的 lab04.
2. **對照組**: 抓一屆 pre-ChatGPT 時代 (2020 或更早) 的鐵人文, 跑同一批指標. 沒有 baseline 就不知道哪個是「AI 拉高的」, 哪個是「一直都這樣」. 對應 lab05.
3. **短文門檻**: 目前排行不設字數 / 句數門檻, 短文密度會跳. 產排行時加 `--min-chars 500` 或 `--min-sentences 20` 濾掉極短文.

**共通結論**: 「訊號 ≠ 判決」比想像中更該強調. 這幾次跑出來的 Top 排名, 沒有一份能拿去說「這些一定是 AI 寫的」— 只能說「這些人的寫作風格特徵剛好跟 AI 常見用法重疊」.
