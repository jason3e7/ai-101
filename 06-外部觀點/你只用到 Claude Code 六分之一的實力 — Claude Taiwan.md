# 你只用到 Claude Code 六分之一的實力

> [!quote]
> "你把它當聊天小助手，它就只會乖乖當助手，被你問一題、答一題。
> 你把它當一個會自己做事的幫手（Agent），等於多一個員工。"

---

## 核心觀點

大多數人用 Claude Code 的方式：
打開視窗 → 貼問題 → 等回覆 → 複製貼上 → 問下一題。

**這樣用沒有錯，但只用到它實力的六分之一。**

> [!tip] 超強新車的比喻
> 就像你買了一台超強新車，結果每次都用手推著走。
> 車子雖然有動，但靠的是你在出力，不是引擎。

根本問題不是工具不夠強，而是**沒有建立正確的使用觀念**：

- 把它當**助手** → 問一題答一題
- 把它當**Agent** → 自己判斷、自己用工具、從頭到尾把任務做完

這兩種用法的差距，不是差一點點，是**數量級**的差距。

---

## 六大核心功能

### 1. CLAUDE.md ＝ 專屬記憶本

在碰你專案程式之前，Claude 會先讀這份檔案。
裡面寫好你的專案架構、寫作習慣、你訂的規矩。

> 沒有這個，你每次聊天都要從頭再解釋一次，
> 像雇一個每天醒來都忘記昨天發生什麼的員工。

### 2. Hooks ＝ 自動規矩、自動品管

在特定時間點（執行工具前後、存檔案時）自動跑設定好的指令。
規矩不用靠「拜託它記得」，是**系統強制把關**。

> 就像工廠的品管流程——不靠人記，制度自動守住標準。

### 3. MCP Server ＝ 給它手腳、讓它能對外接觸

**關鍵中的關鍵。**
本來它只會打字、寫程式。有了 MCP，它能連 GitHub、Slack、資料庫……
不只產生文字，還能**真的去執行、處理真實工作**。

### 4. 子代理（Subagent）＝ 分工合作、同時做多件事

一個主 Claude 負責指揮調度，多個分身同時並行：
有人查資料、有人寫功能、有人測試。

> 不是讓同一個人跑更快，是一次請好幾個員工同時幫你做事。

### 5. Skills ＝ 把你的專業知識存起來

教它一次，把你的專業套路寫成規範檔。
以後遇到同類任務，它自動先讀、照你的標準做事。

> 你的經驗、你的判斷，直接變成它預設內建的能力。

### 6. 電腦操作（Computer Use）＝ 全流程自動封關

不只能寫程式，還能幫你開網頁、填表單、操作電腦畫面。
從想法冒出來，到最後產品上線，整套流程可以自己跑完。

---

## 總結

> [!tip]
> 真正用它做出很強成果的人，都是把這六大功能全部弄懂、全部活用，
> 把它當一套完整工作系統在經營。
> **觀念跟架構，本身就是最大的優勢。**
