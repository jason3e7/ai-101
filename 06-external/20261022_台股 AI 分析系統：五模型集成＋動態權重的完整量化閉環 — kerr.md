# 台股 AI 分析系統 — A Full-Cycle Taiwan-Stock Quant Pipeline

[← 回主頁](../index.md)

> [!NOTE]
> 原文: [kerr20801/taiwan-stock-ai-analyzer](https://github.com/kerr20801/taiwan-stock-ai-analyzer) (MIT, Python, 2026-06 開工、仍在更新)。kerr 自己做的一套台股量化系統: 五個預測模型集成、每天重算權重、盤前盤中盤後一條龍、本地 Ollama 當分析大腦、訊號推 Telegram。**值得收的不是「它能不能賺錢」(它自己在免責聲明就說不保證), 而是它把 ai-101 好幾個散落的主題——[多模型集成](../02-advanced/ml-algorithms-essentials.md)、[本地 LLM](../04-local-llm/ollama-guide.md)、[harness 閉環](../02-advanced/engineering/harness-engineering.md)、[AI 套到動態訊號](../02-advanced/capabilities/capability-from-dynamic-signals.md)——在一個真實跑著的專案裡接成一條線, 剛好拿來對照「工程做到位 ≠ 預測得準」這件事。**

> **TL;DR (EN):** An open-source, actively-maintained Taiwan-stock quant system by kerr. Five ML predictors (LSTM / XGBoost / LightGBM / Random Forest / ARIMA) vote, with weights re-computed daily from each model's recent win-rate / directional accuracy / Sharpe. A full market-day loop (08:30 pre-market gap analysis → 09:00–13:30 per-minute realtime paper-trading → 15:00 post-market institutional-flow review) feeds a local Ollama LLM that writes a diagnosis report, pushed to Telegram. Decision engine blends AI 60% + technicals 25% + sentiment 15%; all trades are simulated (no broker API). The engineering is the lesson — the orchestration and the daily-adaptive weighting — not the alpha: stock prediction is exactly the case that hits the efficiency-market wall, which the author's own disclaimer implicitly concedes.

## 這系統在做什麼 — What It Does

一句話: **把「資料採集 → 五個模型各自預測 → 動態加權投票 → 決策 → 模擬下單 → LLM 寫會診 → 推 Telegram」做成一條每天自動跑的流水線。** 它不是單一模型的 demo, 是一個有排程、有閉環的系統。

三段式的交易日閉環 (full market-day loop):

| 時間 | 階段 | 做的事 |
|:---|:---|:---|
| **08:30** | 盤前 (pre-market) | 拉美股指數、ADR、台指期夜盤、跳空缺口、國際大宗商品, 研判今天怎麼開 |
| **09:00–13:30** | 盤中 (realtime) | 每分鐘掃盤中報價, 算 RSI/MACD/布林, 偵測異常出量, 觸發虛擬撮合 |
| **15:00** | 盤後 (post-market) | 整合三大法人買賣超、融資融券、類股輪動、產業營收, 交給本地 LLM 生成會診報告 |

全部用 `python main.py pre-market / realtime / post-market / screener / train / schedule` 這個統一入口驅動, 排程靠 crontab + systemd service 掛著跑。**所有「下單」都是本地 SQLite 模擬撮合, 不接任何券商 API。**

## 技術骨架 — The Stack

**五模型集成 (ensemble ML matrix)** — 這五個在 ai-101 的 [ML 演算法精要](../02-advanced/ml-algorithms-essentials.md) 都談過:

- **LSTM** (深度學習, 抓長期趨勢) — TensorFlow 或 PyTorch 擇一
- **XGBoost / LightGBM** (梯度提升樹, 抓盤面微結構)
- **Random Forest** (評估指標重要性)
- **ARIMA** (純統計時間序列, 當數理基準線)

**動態自適應權重 (dynamic adaptive weighting)** — 這是整套最有意思的設計: 不用固定權重, 而是依每個模型在**各個別股近 30~60 天**的實際勝率、方向準確度、夏普比率, **每天重算一次投票權重**。等於讓「最近比較準的模型」自動講話大聲一點。

**決策引擎 (decision engine)** — 盤中綜合決策的配比是 **AI 預測 60% + 技術指標 25% + 市場情緒 15%**, 輸出買進 / 賣出 / 觀望。

**本地 LLM (local Ollama)** — 盤前研判與盤後會診交給本機 Ollama (相容 `gemma4` / `llama3.1` / `nemotron` / `phi4`), 零 API 成本、資料不出本機。接法與選型見 [Ollama 指令教學](../04-local-llm/ollama-guide.md) 與 [輕量模型推薦](../04-local-llm/lightweight-models.md)。

**情緒分析 (sentiment)** — 中文新聞情緒用 `snownlp` + `jieba` + `transformers`, 不是只有數字面。

**資料來源**: `yfinance` + `twstock` + 營收 API; **推播**: `python-telegram-bot` (支援 Markdown 長文自動分頁)。台股「1 張 = 1000 股」的交易規則另外抽成 `taiwan_stock_utils.py`。

## 為什麼這個案例值得收 — Why It's Worth Studying

撇開賺不賺錢, 它是幾個 ai-101 觀念的**活教材**:

1. **真正的價值在 harness, 不在某個模型。** 把五個模型、技術指標、情緒、LLM、排程、推播接成一條每天自己跑的閉環, 這個「外層工程」才是難的部分——正是 [Harness Engineering](../02-advanced/engineering/harness-engineering.md) 說的「70% 效能來自外層框架」。任何單一模型抽掉, 系統還在; 閉環抽掉, 就只剩一堆 `.py`。
2. **動態權重 = 一種內建的持續驗證。** 用近期實際勝率重算權重, 本質上是讓系統**用可量化的判准 (勝率/夏普) 持續汰弱留強**, 跟 [AI 產出怎麼驗](../02-advanced/limits-and-verification/verifying-ai-output.md) 的「門檻要可跑可驗」同一個精神, 只是自動化了。
3. **本地 LLM 當「分析層」而非「預測層」** 是務實的分工: 數字預測交給 ML 模型, LLM 只做它擅長的——把一堆指標**彙整成人看得懂的會診報告**。這剛好是 [能力全景圖](../02-advanced/capabilities/ai-capability-landscape.md) 裡「轉換/摘要」類任務, LLM 的強項, 不是叫它去算下一根 K 棒。

## 但別把它當印鈔機 — The Efficiency-Market Wall

這裡要很誠實 (作者自己的免責聲明也這樣講): **工程做到位, 不等於預測得準。** 股市預測正好是 ai-101 [情境擴到感測與市場, 推任務還撐得住嗎](../02-advanced/capabilities/capability-from-dynamic-signals.md) 專門點名的那堵牆:

- **效率市場牆 (efficiency-market wall)**: 真有穩定可預測的訊號, 會被別人搶著套利到消失。Lopez-Lira 等研究顯示, LLM 選股的超額報酬通常 1~2 天就被 drift 掉。
- **混沌牆 + 分佈牆**: 市場是會自我改變的動態系統, 「近 30 天很準」不保證下 30 天還準——這正是為什麼要動態權重, 但動態權重也只是**追著分佈跑**, 不是穿透它。
- **別被完整度騙了**: 系統愈完整、報告愈漂亮, 愈容易讓人**蓋章放行** (rubber-stamp), 這就是 [AI 用久了會鈍化](../02-advanced/limits-and-verification/ai-atrophy.md) 的驗證疲勞。模擬帳戶的漂亮回測, 跟真金白銀的實盤, 中間隔著滑價、流動性與你自己的手。

> [!CAUTION]
> 本筆記是對一個**開源工程專案的技術收錄與架構拆解**, 不是投資建議, 也不對任何個股或這套系統的獲利能力背書。要不要拿它做任何實際金融操作, 請自行獨立判斷並自負盈虧。

一句話收尾: **把它當「一個做得很完整的量化工程範本」來讀, 收穫會比當「一台印鈔機」來讀多得多。** 它示範的是怎麼把 AI 接成一條會自己跑的閉環, 而不是怎麼在效率市場裡穩定獲利——後者沒有人做得到, 前者這個 repo 做得相當漂亮。
