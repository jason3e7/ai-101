# 一人內容工廠實測：AI 自動化流水線省時 90% — A Solo Content Factory: 90% Time Saved

[← 回主頁](../index.md)

> [!NOTE]
> 原文：[超韌性大叔｜一人內容工廠真的可行嗎？大叔實測 7 天 AI 內容自動化流水線](https://www.unclef.tw/ai-content-automation/)
> **一句話：** 50+ 創業者實測 7 天「Claude + Make + ChatGPT」內容自動化，把每輪產出從約 12 小時壓到約 3 小時（省近 90%），但堅持「70 分 AI 初稿 + 30 分人腦靈魂」。

> **TL;DR (EN):** A 50-something solo creator ran a 7-day test of a Claude + Make + ChatGPT content pipeline, cutting per-cycle production from ~12h to ~3h (~90%). Core lesson: automate the skeleton, keep humans for the 30–40% that carries brand voice and lived experience. Two companion pieces cover multi-platform writing (Claude) and one-click auto-publishing (Claude + n8n).

---

## 核心成果：省時對照 — The Numbers

作者 Darren（超韌性大叔）用 Claude 的 Skill 系統當文字引擎，實測一輪完整內容產出的前後對比：

| 環節 | 自動化前 | 自動化後 | 工具 |
|---|---|---|---|
| 議題搜集 | 360 分 | 15–20 分 | Claude + Make |
| SEO 文章 | 360 分 | 30–40 分 | Claude Skill 01 |
| IG 輪播圖文案 | 120 分 | 10–15 分 | Claude Skill 02 |
| 其他社群（Threads/FB/Line） | 60–90 分 | 20–30 分 | Claude Skill 03–05 |
| YouTube 腳本 | 120 分 | 20–30 分 | Claude Skill 06 |
| **總計** | **~12 小時** | **~3 小時** | **省近 90%** |

> [!IMPORTANT]
> 關鍵不是「AI 全自動」，而是把重複勞動壓縮，把省下的時間還給「只有人能做的部分」。

---

## 三層自動化工作流 — The Three-Layer Pipeline

作者把流程拆成三層，自動化程度由高到低：

1. **搜尋選題（自動化 ~80%）**
   Make.com 定時觸發 → Claude Skill 07 掃描 AI 新訊與創業趨勢 → 產出「選題週報」 → 人工確認約 15 分鐘

2. **文字生產（半自動化 60–70%）**
   輸入背景素材 + 個人觀點 → 依序啟動 Skill 01–06 產初稿 → 人腦補進 30–40% 親身經歷與獨特觀點

3. **視覺生產（人工觸發）**
   Claude 產提示詞 → ChatGPT Image 2.0 手動生圖 → 微調 1–2 次

**工具分工**：Claude（文字核心 + Skill 引擎）、ChatGPT Image 2.0（生圖）、Make.com（排程觸發）、Gemini/Antigravity（輔助）；Canva 使用頻率下降。

## 輔篇一：怎麼用 Claude 寫多平台貼文 — Writing for Each Platform

第二層「其他社群」那格怎麼做，[moksaweb 的教學](https://moksaweb.com/claude-for-social-media/) 補了細節——用 Claude 一次產出多平台版本的 4 步驟：

1. **設定品牌調性**：品牌個性、目標平台、TA 畫像
2. **要 Hook 5 版本**：選前 3 秒最吸睛的開場（問題式、數據式、爭議式⋯⋯）
3. **產 4 個平台版本**：IG（emoji、視覺化）、Threads（短句聊天感）、FB（生活分享）、LinkedIn（專業）
4. **Hashtag + 時段**：在地標籤（`#台北美食`）+ 主題 + 品牌三層；抓黃金時段

**台灣在地要點**：Threads 黃金時段「週四晚 8–9 點」；中文在地標籤互動遠勝英文；Claude 相較 ChatGPT 的優勢是繁中道地、不亂編產品功效（避免違反 NCC）。

---

## 輔篇二：最後一哩——自動發布 — The Last Mile: Auto-Publishing

unclef 的 Make 負責「排程觸發」，但「真正把內容送上各平台」這一哩，[攝影師林的 Threads 分享](https://www.threads.com/@lin__photograph/post/DSWE-u4iQo0/) 講得更深——他花了半年搞定「一鍵授權 Claude + n8n，自動發文到 FB、YouTube、Threads」。

痛點很有共鳴：同一支影片、同一篇文，要手動登入 FB 上傳、YouTube 發布、Threads 貼文⋯⋯操作不難，但**日復一日的點擊複製會磨損創作熱情**。用 n8n（開源自動化，類似 Make）串起各平台 API 授權後，發布這段就能無人化。

> [!NOTE]
> Make.com（商用、易上手）和 n8n（開源、可自架）是這類自動化流水線最常見的兩個「觸發與串接」引擎，兩篇各用一個，可視預算與隱私需求二選一。

## 核心原則：70 分 AI + 30 分人腦 — The 70/30 Rule

三篇的共同結論，也是最值得記的一句：

> **AI 給穩定的 70 分骨架，人補上 30–40 分的靈魂。**

人腦不可取代的部分：
- 親身踩過的坑、在地創業情境
- 獨特語氣與自創理論
- 事實查核與品牌溫度校準

這對應 Google EEAT 的「真實經驗（Experience）」與「權威性」——**完全自動化的文章「正確但不活著」**。

---

## 坑與限制 — Pitfalls

作者實測點出四個風險：

1. **品質不穩**：全自動產出正確但無生命力
2. **事實查核缺口**：無人把關易出錯
3. **品牌溫度消失**：作者當下心情狀態傳不出去
4. **長期偏移**：無校準會慢慢偏離品牌個性 → 建議**每季校準一次 Skill 設定**

---

## 我的重點提煉 — Takeaways

- **省時來自「拆層 + 分工」**，不是單一神器：選題（自動）、文字（半自動）、視覺（人工），各層自動化程度本就該不同。
- **Claude 的角色是 Skill 引擎**：把每種內容（SEO 文、IG 文案、各社群）各做成一個 Skill，重複呼叫——這和 ai-101 的 skill 化思路一致。
- **人力該投在「發散端 + 校準」**：AI 擅長穩定產骨架（收斂／轉換），人負責獨特觀點（發散）與事實把關，正是 [四種能力執行手冊](../02-advanced/four-capabilities-playbook.md) 的分工。
- **發布自動化選型**：易上手選 Make，要開源自架選 n8n。
