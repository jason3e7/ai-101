# Boris Cherny：幾乎不用 plan mode 了，直接 auto mode

> [!info]
> 原文：[Claude Taiwan 社群貼文](https://www.facebook.com/groups/1224997379198346/posts/1308638740834209/)
> 引用來源：Boris Cherny 在 X 上的分享
> **一句話：** Claude Code 的核心人物 Boris Cherny 說他現在幾乎不用 plan mode 了——「Opus 4.7 已經夠聰明，有需要它會自己問」——但社群作者的理由不同：是用自己的 skills 取代了 plan mode。

---

## Boris Cherny 說了什麼

> 「這幾天我心中第一名的 Claude Code tips 是使用 auto mode」

當被問到「推薦先用 plan mode 再搭配 auto mode 嗎？」他的回應：

> 「我現在不太用 plan mode 了，大多直接 auto mode。因為 Opus 4.7 已經夠聰明，而且有需要他會自己問。」

### 值得注意的轉變

Boris Cherny 過去曾明確推薦：「大多情況下從 plan mode 開始」——這與他現在的說法完全相反。

---

## Plan mode vs Auto mode

| 模式 | 說明 |
|---|---|
| **Plan mode** | Claude 先規劃、列出步驟、等人確認後再執行 |
| **Auto mode** | Claude 自行判斷何時思考、何時直接行動 |

Boris Cherny 的論點：Opus 4.7 夠聰明，會在需要確認時主動發問，不需要人為強制進入 plan mode。

---

## 社群作者的觀察

作者自己也幾乎不用 plan mode，但原因不同：

> 「我有自己的 skills 取而代之。」

這說明「不用 plan mode」有兩種路徑：
1. **模型夠強路徑**（Boris Cherny）：升到 Opus 4.7，模型本身有足夠判斷力
2. **框架替代路徑**（作者）：用自訂 skills 結構化工作流，不依賴 plan mode

### 作者對 4.7 的態度

> 「我還停在 4.6，剛推出的時候對 4.7 的提升沒特別感覺，只感覺 token 燒得特別快」

---

## 討論問題

> 「4.7 真的有讓你覺得可以跳過 plan mode 嗎？」

這個問題指向一個更深層的判斷：**plan mode 的價值是模型能力不足時的補償，還是本身就是好的工作流設計？**
